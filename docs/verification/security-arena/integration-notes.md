# Evidence provenance

The original red and white agents received separate copies of baseline `074ee0a` and independent briefs. They were instructed not to read the opponent's copy or plans; the shared filesystem is not a hard isolation boundary. The second red round received the public candidate and no request-signing key or authenticated user context. Its ordinary permission matrix is a bounded regression exercise, not an unrestricted penetration test.

`red-baseline.json` records 22 desired-denial failures and nine durable side effects under the explicitly trusted legacy contract. `white-red.json` and `white-action-red.json` preserve the defensive agent's initial behavior failures. The white receipts describe that candidate's local state; their pending integration fields are historical, not the final CI result. `hardened-red.json` and `hardened-red-trust.json` independently repeat the original matrix and add private/API/worker denials, using SCRAM and trust authentication respectively. Trust mode proves authorization under the selected SQL identity, not password authentication.

`profile-default-red.txt` contains the actual default-configuration behavior failure before changing the binary default. `profile-summary-red.txt` shows that omitting three new startup regressions could previously still produce a green summary. The gate stale-report and coverage/timeout receipts preserve actual RED and GREEN output with source/test hashes: old evidence cannot stand in for a fresh run, missing scale/property tests cannot pass, and timeout following an assertion cannot kill a mutant. The binding and gate scaffold receipts are missing-symbol/import failures, not discovered product defects.

The large-read receipts distinguish the initial real query-plan regression, a repaired EXPLAIN test helper, and a later bulk-fixture setup timeout. Only completed behavioral failures are RED evidence for the read fix. The final custom/generic plans and independent randomized pagination model are separate from the original credential matrix.

Published core migrations and pinned hashes are unchanged. The additive SQL profile requires installation, fresh dedicated logins and an independent signing key. The binary defaults to this profile; explicit `legacy` retains the old credential risk. A stolen worker login still controls its own warehouse's maintenance capabilities. Application/key/admin compromise and denial of service remain outside the password-only protection claim.

The required GitHub Actions workflow independently runs the legacy kernel suite and its 93 mutations, the hardened SQL/HTTP/race/scale/property suite and four profile mutations, the frozen independent permission matrix, and process-crash/WAL/isolated-restore experiments. Passing local receipts do not establish final pipeline success. The final workflow must pass on the exact delivered revision with no required job or step skipped.
